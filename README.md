# Local PDF Toolkit

> The desktop app and the v0.2.0 installers still carry the earlier working name
> "OpenPDF" (the app, the package files and the docs below use it). Not to be confused with [LibrePDF/OpenPDF](https://github.com/LibrePDF/OpenPDF),
> an unrelated Java library for creating PDFs.

A PDF editor for people (desktop app and browser) and a PDF toolkit for programs
and AI agents (REST API and MCP), running entirely on your own computer. Nothing
is uploaded anywhere.

**Installers:** Linux .deb and AppImage, v0.2.0, at
[github.com/gary1381/openpdf-releases](https://github.com/gary1381/openpdf-releases).

## Features

- **Edit**: change the page's text, add text, highlight, comment, fill in forms, sign (drawn,
  typed or image signatures, and digital signatures with a certificate), insert
  images, rotate / reorder / delete / extract pages, combine files, print.
- **Process**: OCR for scans, password protection and removal, flattening,
  text extraction, page rendering, true redaction with a verification pass.
- **For agents**: every feature is a REST endpoint; the
  [PDF Engine](./engine/README.md) packages them as MCP tools (reading, search,
  OCR, form filling, true redaction, signing…) for Claude, Cursor and other
  MCP clients. An optional add-on reads documents the way a language model
  needs them: headings, reading order across columns, tables, as Markdown or
  as elements with their page and position.
- **Languages**: the interface is available in English, German, French,
  Spanish, Simplified Chinese, Traditional Chinese, Japanese and Korean (see
  [docs/TRANSLATING.md](./docs/TRANSLATING.md)).

More detail, and how it differs from other PDF software: [docs/FEATURES.md](./docs/FEATURES.md).

Built on open-source components, each used unmodified:

- **Apache PDFBox** (Apache-2.0): reading, metadata, annotations, writing text, signatures
- **qpdf** (Apache-2.0): combine / split / rotate / delete and reorder pages / encrypt / unlock / flatten
- **OCRmyPDF** (MPL-2.0) + **RapidOCR** (Apache-2.0, PaddleOCR models): OCR, English and Chinese
  together (an optional component, installed the first time it is used; see below)
- **Docling** (MIT, IBM layout and table models): document structure for agents (an optional
  component: `./scripts/install-structure.sh`)
- **pdf.js** (Apache-2.0): display in the editor (bundled in this repository)
- **WenQuanYi Micro Hei** (Apache-2.0 / GPLv3 with font embedding exception): a CJK font for
  writing into PDFs (installed in the container from Ubuntu; not in this repository)

Third-party licences: [THIRD-PARTY-NOTICES.md](./THIRD-PARTY-NOTICES.md).

## Repository layout

| Folder | What it is |
|---|---|
| `gateway/` | FastAPI gateway: REST API, editing sessions, and the editor UI (`gateway/app/static`) |
| `services/` | Sidecar services: `pdfbox/` (Java, Apache PDFBox), `qpdf/`, `ocr/` (OCRmyPDF + RapidOCR), `structure/` (Docling), `model/` (optional local document-reading model) |
| `engine/` | PDF Engine: one container with all services plus an MCP server for agents |
| `mcp/` | An older, minimal MCP server that talks to a running gateway |
| `web/` | The same editor as a static site; its services run in the page (PDFium WebAssembly in a Web Worker) |
| `desktop/`, `packaging/` | Tauri desktop app; Linux .deb / AppImage build and install tests; Windows / macOS work in progress |
| `benchmarks/` | Parsing (olmOCR-Bench) and redaction comparisons, with their scripts and results |
| `scripts/` | Start scripts, add-on installers, browser end-to-end checks |
| `prototypes/` | The OCR engine comparison (Tesseract vs RapidOCR) that led to the current OCR service |
| `docs/` | Features, architecture and performance, OCR models, release-readiness review, translating |

## Benchmarks

**Reading PDFs for agents** ([benchmarks/parsing](./benchmarks/parsing/README.md)):
[olmOCR-Bench](https://huggingface.co/datasets/allenai/olmOCR-bench) (Ai2, ODC-BY;
1,403 single-page PDFs, about 7,000 pass/fail checks, scored by the benchmark's own code).

| System | Average without the two math categories (6 categories) | Overall (8 categories) | s/page |
|---|---|---|---|
| Docling 2, default settings (OCR on) | 71.6 | 53.7 | 19.0 |
| **Local PDF Toolkit `pdf_read_markdown`** (OCRs scans and pictures itself) | **71.3** | **53.5** | 7.8 (CPU only) |
| PyMuPDF4LLM 2.0 | 50.2 | 37.7 | 2.4 |

The overall score is held down by the two math categories, which score 0
because formulas come out as plain characters, not LaTeX. With an optional
document-reading model on the GPU (PaddleOCR-VL), the overall score is 67.5
(see [docs/OCR-MODELS.md](./docs/OCR-MODELS.md)). Timings are median wall time
per page on one shared machine.

**Redaction** ([benchmarks/redaction](./benchmarks/redaction/README.md)): 13
documents designed for this test (generated by `benchmarks/redaction/corpus.py`)
put the secrets where redaction tools tend to miss them: comments, form fields,
document properties, bookmarks, attachments, `/ActualText`, scanned pixels. The
redacted files are then searched with tools that had no part in the redaction.

| Tool | Clean (of 13) |
|---|---|
| Local PDF Toolkit, desktop / server (PDFBox) | **13** |
| Local PDF Toolkit, browser (PDFium WASM) | **13** |
| PdfCraft 0.18.2, redact + Sanitize | 13 (Sanitize also removes every comment, bookmark and attachment) |
| Stirling-PDF 3.2.1, convert to image | 10 |
| PyMuPDF 2.0 + `scrub()` | 9 |
| Stirling-PDF 3.2.1, auto-redact | 8 |
| pdf-redactor 0.0.1 | 4 |

The test set was designed by the author of this toolkit, so read it as a check of
the cases it covers, not as an independent ranking. Full table and per-case
results: [benchmarks/redaction/README.md](./benchmarks/redaction/README.md).

## In the browser (nothing to install)

[web/](./web/README.md) builds the same editor as a static site whose services
run inside the page (WebAssembly in a Web Worker): open it, open a PDF, and the
file never leaves the computer. Editing, forms, signatures (also digital),
true redaction with its check, text boxes and OCR all work there, offline too
once loaded; only the agent tools (MCP) need the local services. Every part of
it has a licence that allows commercial use.

```bash
cd web && npm install && node build.mjs --serve   # http://127.0.0.1:28300
```

To put it on a website for other people: [web/DEPLOY.md](./web/DEPLOY.md).

## Install (Linux desktop app)

Download the .deb or AppImage from
[openpdf-releases](https://github.com/gary1381/openpdf-releases/releases) (v0.2.0,
with `SHA256SUMS`). The installer brings all its background services: no
Python, Java, Podman or Docker needed.

- **.deb** (Ubuntu 22.04+, Debian 12+): `sudo apt install ./OpenPDF_<version>_amd64.deb`, then open
  OpenPDF from the applications menu.
- **AppImage** (other distributions): `chmod +x OpenPDF_<version>_amd64.AppImage`, then run it.

Text recognition (OCR) is an add-on, about a 170 MB download. The first time you
use OCR, click **Download and install**; it works right after.

Windows and macOS installers are in progress ([packaging/desktop/README.md](./packaging/desktop/README.md)). How the Linux packages are built
and tested: [packaging/linux/README.md](./packaging/linux/README.md). The quick
start below is for development and servers (containers).

```
              ▼                       ▼
        Gateway :8090  (editor UI, REST API; editing sessions on disk)
              ├── OCR service :8091 (optional)
              ├── Structure service :8094 (optional, Docling)
              ├── PDFBox service :8092
              └── qpdf service :8093
```

## Quick start (containers)

```bash
cp .env.example .env   # optional: set API_KEY

# Podman (recommended): starting takes seconds; images are built the first time
./scripts/start.sh
# rebuild all images after changing the code
./scripts/run-podman.sh

# or Docker Compose
docker compose up -d --build

curl http://127.0.0.1:8090/health
./scripts/e2e.sh
```

The containers restart automatically: with Podman through the user service
`podman-restart.service` (`run-podman.sh` enables it), so they come back after a
reboot.

**Safe defaults**: the services listen on 127.0.0.1 only and are not reachable
from other machines; they only accept requests whose Host is `127.0.0.1` or
`localhost`, and refuse cross-site requests from other web pages. To serve a
local network, set all three:

```bash
BIND_ADDR=0.0.0.0 API_KEY=a-long-random-string ALLOWED_HOSTS=127.0.0.1,localhost,192.168.1.105 ./scripts/run-podman.sh
```

**Interface**:

- Browser: <http://127.0.0.1:8090/>: tabs, thumbnails, Edit text / Add text / Comment, highlights,
  forms, signatures, print preview.
- Desktop: `./scripts/start-desktop.sh`, or see [desktop/README.md](./desktop/README.md) (Tauri).
- Common shortcuts: Ctrl+O open, Ctrl+S save, Ctrl+Z / Ctrl+Y undo / redo, Ctrl+F find,
  Ctrl+P print, `?` all shortcuts.

OpenAPI documentation: <http://127.0.0.1:8090/docs>

**Architecture and performance** (editing sessions, deferred syncing):
[docs/ARCHITECTURE-AND-PERFORMANCE.md](./docs/ARCHITECTURE-AND-PERFORMANCE.md)

## API key

Routes under `/v1/pdf/*` take the header:

```http
X-API-Key: pdf-gateway-dev-key
```

- **Off by default** (`API_KEY` is empty).
- To turn it on, set `API_KEY=your-key` in `docker-compose.yml` or the environment.
- The editor then asks for the same key (**Settings → API Key**); programs send `X-API-Key`.
- `/health` needs no key.

## REST API

| Method | Path | What it does |
|--------|------|--------------|
| POST | `/v1/pdf/register` | Upload a file and open an editing session; returns `document_id` |
| POST | `/v1/pdf/document/{id}/restore` | Go back to a version (undo / redo) |
| DELETE | `/v1/pdf/document/{id}` | Close a session |
| POST | `/v1/pdf/merge` | Several files `files[]` → one combined PDF |
| POST | `/v1/pdf/split` | `file` or `document_id` + `pages` (e.g. `1-3`) |
| POST | `/v1/pdf/pages` | Keep and reorder pages: `order=3,1,2` (pages not listed are deleted) |
| POST | `/v1/pdf/ocr` | `file` + `languages` (e.g. `eng,chi_sim`); pages without text are recognised and, with `pictures=true` (the default), the pictures on the other pages; 503 with `X-Error-Code: ocr_not_installed` when the OCR component is missing |
| POST | `/v1/pdf/extract-images` | `file` or `document_id`, `pages`, `min_size`, `ocr` (default true): a ZIP of the pictures (JPEGs unchanged, others PNG) with `manifest.json` (page, box, pixel size, text read in each) and a `.txt` per picture |
| POST | `/v1/pdf/from-images` | `files` (JPEG, PNG, TIFF, GIF, BMP; one page each), `ocr` (default true), `languages`: a PDF, searchable when OCR is installed |
| POST | `/v1/pdf/export` | `file` or `document_id`, `format` (`markdown` or `json`), `pages`, `ocr` (default true): a ZIP with the document as Markdown or JSON and its pictures in `images/` (needs the structure component) |
| GET | `/v1/pdf/ocr/status` | Whether the OCR component is installed: `{"installed": true}` |
| POST | `/v1/pdf/structure` | `file` or `document_id`, `pages` (e.g. `1-3,5`): headings, paragraphs, lists, tables and figures in reading order, with page, box and section, plus Markdown per page. Scans and pictures are OCR'd first (`ocr=false` to skip); the text in a picture is its `text`. 503 with `X-Error-Code: structure_not_installed` when the component is missing |
| GET | `/v1/pdf/structure/status` | Whether the document structure component is installed |
| POST | `/v1/pdf/extract` | All text |
| POST | `/v1/pdf/info` | Page count and metadata |
| POST | `/v1/pdf/annotate` | Add a sticky note |
| POST | `/v1/pdf/callout` | Callout box with leader line and arrow, drawn into the page |
| POST | `/v1/pdf/draw-text` | Write text into the page content (PDFBox, Helvetica) |
| POST | `/v1/pdf/highlight` | Highlight an area (PDFBox) |
| POST | `/v1/pdf/remove-highlight` | Remove highlight annotations inside an area |
| POST | `/v1/pdf/replace-text` | Paint over an area and write text (page content) |
| POST | `/v1/pdf/read-placements` | Read the editor's text boxes and comments (kept in the metadata) |
| POST | `/v1/pdf/embed-placements` | Save the editor's text boxes and comments: kept in the metadata, drawn into the pages (layer “OpenPDF edits”); Edit text boxes remove what they cover |
| POST | `/v1/pdf/sign` | Place a signature image (PDFBox, PNG/JPEG) |
| POST | `/v1/pdf/stamp-signatures` | Place several signature images at once: `images` + `placements=[{page,x,y,width,height,image}]`, `mode=flatten` (part of the page) or `annotation` (a stamp) |
| POST | `/v1/pdf/digital-sign` | Digital signature with a .p12/.pfx certificate (PAdES, incremental save); into an existing signature field (`field_name`), a dragged-out area, or invisible; optional `tsa_url` timestamp |
| POST | `/v1/pdf/verify-signatures` | List the digital signatures in a file: signer, time, intact or not, changed after signing or not |
| POST | `/v1/pdf/cert-info` | Read a certificate (checks its password) |
| POST | `/v1/pdf/generate-cert` | Create a self-signed personal certificate (returns a password-protected .p12) |
| POST | `/v1/pdf/form-fields` | List form fields (PDFBox) |
| POST | `/v1/pdf/fill-form` | Fill in an AcroForm: `values={"field":"value"}` |
| GET | `/v1/pdf/document/{id}/meta` | Version of the session's PDF (revision / etag / size) |
| GET | `/v1/pdf/document/{id}` | Download the session's PDF (supports `Range`, 206) |
| POST | `/v1/pdf/render-page` | PNG of one page (`page_index`, `scale`) |
| POST | `/v1/pdf/unlock` | Remove a password (qpdf) |
| POST | `/v1/pdf/flatten` | Flatten annotations / forms (qpdf or PDFBox) |
| POST | `/v1/pdf/rotate` | Rotate clockwise; `pages` picks pages (e.g. `1,3-5`), empty for all (qpdf) |
| POST | `/v1/pdf/encrypt` | A copy with an open password (qpdf) |

The agent-oriented endpoints used by the PDF Engine (page text with positions,
find text, text layout, true redaction and its verification) are described in
[engine/README.md](./engine/README.md). How the redaction compares with other
tools (PyMuPDF, Stirling-PDF, pdf-redactor), checked independently:
[benchmarks/redaction](./benchmarks/redaction/README.md).

Except for `merge` and `register`, endpoints take either `file` (the result file
comes back directly) or `document_id` (the session is changed and JSON with the
new `revision` comes back; changes to one session run one after another). The
upload limit is 200 MB by default.

### Examples

```bash
KEY=pdf-gateway-dev-key

# combine
curl -H "X-API-Key: $KEY" -F "files=@a.pdf" -F "files=@b.pdf" http://127.0.0.1:8090/v1/pdf/merge -o merged.pdf

# OCR (English and Chinese together). OCR is an optional component
# (about 190 MB to download, about 620 MB installed); install it first: ./scripts/install-ocr.sh
curl -H "X-API-Key: $KEY" -F "file=@scan.pdf" -F "languages=eng,chi_sim" http://127.0.0.1:8090/v1/pdf/ocr -o searchable.pdf

# extract text
curl -H "X-API-Key: $KEY" -F "file=@doc.pdf" http://127.0.0.1:8090/v1/pdf/extract

# document structure for an LLM: Markdown and elements with pages and boxes.
# Optional component (Docling, CPU only, about 2 GB installed): ./scripts/install-structure.sh
curl -H "X-API-Key: $KEY" -F "file=@report.pdf" -F "pages=1-5" http://127.0.0.1:8090/v1/pdf/structure
```

The structure service does no OCR: scanned pages are listed in
`pagesWithoutText`; OCR the file first. Expect a few seconds per page on a
CPU; the last few results are kept, so reading a document part by part does
not convert it again.

## MCP (Claude, Cursor and other agents)

Use the **PDF Engine** in [engine/](./engine/README.md): one container image
with all services and an MCP server with 29 tools (read, search, render, OCR,
fill forms, true redaction, sign and verify, combine, split, rotate, encrypt…).

The older minimal MCP server in `mcp/server.py` (merge, split, OCR, extract
text, info) talks to a running gateway:

```bash
python3 -m venv .venv-mcp
source .venv-mcp/bin/activate
pip install -r mcp/requirements.txt
export PDF_GATEWAY_URL=http://127.0.0.1:8090
python3 mcp/server.py
```

Add [mcp/cursor.mcp.json.example](./mcp/cursor.mcp.json.example) to Cursor's MCP settings.

## Local development (gateway only)

```bash
cd gateway
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export QPDF_URL=http://127.0.0.1:8093 OCR_URL=http://127.0.0.1:8091 PDFBOX_URL=http://127.0.0.1:8092 \
  STRUCTURE_URL=http://127.0.0.1:8094
uvicorn app.main:app --reload --port 8090
```

Interface texts: write them in English through `t()` and run
`python3 scripts/i18n.py check` (see [docs/TRANSLATING.md](./docs/TRANSLATING.md)).

### Tests and checks

- `python3 engine/tests/make_fixtures.py OUT_DIR` builds the test PDFs (contract,
  form, scan, report); `engine/tests/test_mcp.py` and `test_http.py` run the
  MCP tools end to end against a running engine (see [engine/README.md](./engine/README.md#building)).
- `scripts/e2e.sh` checks a running gateway; `scripts/check_*.py` are focused
  checks (redaction text, edits baked into pages, forms, PWA, UI languages)
  against a dev stack, several of them in a headless browser (Playwright).
- `web/test/check_web.py` checks the browser build; `packaging/linux/test/`
  installs the .deb / AppImage in clean containers and probes them.
- `benchmarks/redaction/run.py` and `benchmarks/parsing/` reproduce the benchmark results.

|----------|---------|--------|
| `BIND_ADDR` | `127.0.0.1` | Listening address (`run-podman.sh` / compose) |
| `API_KEY` | empty | When set, every `/v1/pdf/*` request needs `X-API-Key` |

## Limitations

- **Platforms**: released installers are Linux only (.deb, AppImage). Windows
  and macOS installers have a build workflow
  ([packaging/desktop/README.md](./packaging/desktop/README.md)) but are not
  released or signed yet.
- **Release status**: v0.2.0 is an early release. A pre-release review from 2026-10-13
  ([docs/RELEASE-READINESS.md](./docs/RELEASE-READINESS.md)) lists the known
  gaps; restart tests on installed builds are still to do.
- **OCR** is set up and tested for English and Chinese.
- **Formulas** are not converted to LaTeX by default (the two math categories
  of olmOCR-Bench score 0 without the optional model).
- **Redaction** cannot see words inside pictures on pages that also have a text
  layer; such pages are listed in the report so they can be checked and redacted
  by region. Always look at the result before sending it.
- **The PDF Engine image** (`ghcr.io/gary1381/pdf-engine`) is not published yet;
  build it from `engine/Dockerfile`.
- The web build, the add-ons and the services download their dependencies and
  models from their upstream projects when built or installed; nothing large is
  stored in this repository.
